# 2026-09-05 外部输入卡

## 候选来源

### 来源 1：Visibility of System Status (Usability Heuristic #1)

- URL: https://www.nngroup.com/articles/visibility-system-status/
- 访问日期：2026-09-05
- 看到的机制/设计：Nielsen Norman Group 把“系统状态可见”放在可用性启发式第一条，强调界面应及时告诉用户发生了什么、动作结果是什么、下一步该怎么判断。文章举了站点、等待时间、当前位置等反馈例子。
- 与铁匠铺场景的关系：昨天的四站巡铺已经告诉访客“当前在哪一站”，但点击后没有留下“我已经看过哪里”的回执。铁匠铺可以把这种状态反馈转译为“已看几站、下一锤去哪”，让巡铺更像一条有火候记录的路线。

### 来源 2：Understanding Success Criterion 4.1.3: Status Messages

- URL: https://w3c.github.io/wcag/understanding/status-messages
- 访问日期：2026-09-05
- 看到的机制/设计：W3C 对状态消息的解释强调，重要内容变化不一定要抢焦点，但应该能被程序化识别并由辅助技术提示；这样看不到视觉变化的用户也能知道操作结果。
- 与铁匠铺场景的关系：底部当前站提示已经用了 `aria-live`，今天如果加入巡铺进度，也应同步 `progressbar` 的 `aria-valuenow` 和 `aria-valuetext`，避免它只是视觉装饰。

### 来源 3：Tips for Immersive Walkthroughs That Actually Work

- URL: https://rendimension.com/blog/tips-for-immersive-walkthroughs/
- 访问日期：2026-09-05
- 看到的机制/设计：文章认为沉浸式 walkthrough 的关键不是堆高纹理细节，而是稳定的相机、可信光照和清楚的叙事弧；好的游览路径能建立上下文、连接空间并以有氛围的节点收束。
- 与铁匠铺场景的关系：老杨铁匠铺不需要继续加 3D 物件证明迭代。更贴合的是让现有“老杨 → iLoop → 近况 → 火炉”形成可完成的叙事弧：走过的站留下痕迹，未走的站给下一步。

## 消化与选择

三个来源共同指向一个原则：访客完成动作后，页面要给出可见、可理解、可被辅助技术读到的反馈。昨天已经做了“当前站提示”，今天如果继续扩展导览，重点不该是再写更多介绍，而是补“巡铺回执”：哪几站已经看过、现在进度到哪里、下一站建议去哪。

我拒绝做新的 3D 路牌、地面脚印或炉光追踪。它们视觉更强，但会回到新增装置的路线，也可能触碰模型协作红线或灯光模式风险。今天的转译是把铁匠铺巡铺当成一条四锤路线：底部导览条加入进度线、已看状态和下一站提示；四站走完后给“巡铺完成”的收束语。

## 创意方案竞争

### 方案 A：巡铺回执与进度

- 新颖度：3/5。进度条本身常见，但把它嵌进铁匠铺四站巡铺，让“看过哪些锚点”可见，是对现有路线的明确升级。
- 访客价值：5/5。首次访客能知道自己已经看过老杨、iLoop、近况或火炉中的哪几站，也能看到下一站建议，降低迷路和重复点击。
- 场景贴合度：5/5。铁匠铺本来强调闭环和取证，已看回执像炉前记录，不改变独立 3D 展示页本质。
- 视觉影响：3/5。默认首屏底部会多一条进度线和“已看 1/4”，5 秒内可见，但不会遮挡人物和火炉。
- 实现风险：2/5。只扩展现有导览 DOM、CSS 和状态同步，不碰模型、灯光预设、渲染循环或音频时序。

### 方案 B：站点完成后的角色短回声

- 新颖度：4/5。每到一站后由对应 NPC 冒出一句“这一锤看完了”的短回声，会更有角色感。
- 访客价值：4/5。反馈更生动，但可能和现有对话气泡、随机吐槽、语音播放互相打断。
- 场景贴合度：4/5。人物回声符合铺内叙事，不过容易让导览变吵。
- 视觉影响：3/5。气泡变化明显，但默认截图不一定体现完整路径。
- 实现风险：3/5。需要协调 `showBubble`、自动说话、火炉模式语音和关闭状态，可能引入打断 warning 或状态错位。

### 方案 C：四站完成后切入火炉收束模式

- 新颖度：4/5。访客走完四站后自动把场景切到火炉模式，形成“逛完开炉”的戏剧收束。
- 访客价值：4/5。完成感强，也能引导去锻欢迎语。
- 场景贴合度：5/5。以火炉收束很符合铁匠铺。
- 视觉影响：4/5。灯光、火焰和音乐会明显变化。
- 实现风险：4/5。会触碰场景模式、BGM 解锁、NPC 自动说话和火焰脉冲，容易造成未授权播放或视觉过热。

## 选择与完整体验

- 最终选择：方案 A，巡铺回执与进度。
- 访客会看到什么：底部巡铺提示下方出现“已看 1/4”的进度线和“下一站：iLoop”；走到其他站后已看数字、进度线和下一站同步更新，已看按钮留下轻微标记。
- 访客能做什么：访客可以按昨天已有的鼠标点击、上一站/下一站按钮或左右方向键巡铺；每到一站都会留下已看状态。
- 访客得到什么：四站路线从“当前说明”进一步变成“可完成的参观路径”，访客知道自己已经理解了哪些铺内内容，也知道下一步去哪。

未选方案 B 的原因：角色短回声更活，但和现有 NPC 气泡、自动说话和语音容易重叠，今天的目标是清晰回执，不是增加声音和气泡复杂度。未选方案 C 的原因：火炉收束更有戏剧性，但它会牵动高风险的灯光和音频时序；当前更稳妥也更贴题的是把完成感先做在导览条里。
