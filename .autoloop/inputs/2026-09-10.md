# 2026-09-10 外部输入卡

## 公开来源候选

### 来源 1

- 标题：Digital labels
- URL：https://dls.tepapa.govt.nz/_pages/principles/digital-labels/
- 访问日期：2026-09-10
- 看到的机制/设计：Te Papa 的数字标签指南强调，数字标签应服务于展品对象本身，而不是用复杂线性故事盖过对象；内容要 broad and shallow，首层先给出关键结论和对象描述；物理摆放要做到从对象能找到标签、从标签能看回对象；UI 要有 natural mapping，并避免含糊的 “Next / Touch here” 式链接。
- 与铁匠铺场景的关系：铁匠铺已有底部四站导览和空间炉钉，但可点击目标主要仍靠访客猜测或读底部按钮。可以把“从对象到标签、从标签回对象”的原则转译成贴在三位 NPC 和火炉旁的小炉扣：编号、站名、可点击，直接把可操作性放到对象附近。

### 来源 2

- 标题：three.js css2d - label
- URL：https://threejs.org/examples/css2d_label.html
- 访问日期：2026-09-10
- 看到的机制/设计：three.js 官方示例用 `CSS2DRenderer` 和 `CSS2DObject` 把 HTML 标签绑定到 3D 场景对象上，标签保持可读，随相机和对象位置同步。示例也说明 WebGL 与 DOM 标注可以协作，不必把所有说明都做成 3D 几何。
- 与铁匠铺场景的关系：本页已经在上一轮用 `Vector3.project()` 做了当前站炉钉，不需要再引入 CSS2DRenderer。今天可以复用这套投影能力，把四个“可点触点”贴到对应站点附近，保持零构建单文件，同时让点击入口更直观。

### 来源 3

- 标题：Beyond Blue Links: Making Clickable Elements Recognizable
- URL：https://www.nngroup.com/articles/clickable-elements/
- 访问日期：2026-09-10
- 看到的机制/设计：公开搜索结果摘要指出，用户会通过视觉外观判断一个元素是否可点击；这类能暗示用途的可感知线索被称为 signifiers。页面抓取时连接 `www.nngroup.com` 超时，因此本轮只使用搜索结果摘要作为可追溯输入，不复制正文。
- 与铁匠铺场景的关系：当前三位 NPC 和火炉虽然能点，但默认画面里只有底部文字告诉访客“点击人物或火炉”。把四个站点做成小号、清晰、可聚焦的炉扣，是给对象补 signifier，而不是新增一套复杂导航。

## 消化与选择

今天可借用的原则：

- 数字标签应贴着对象工作，帮助访客先理解“这个对象能告诉我什么”。
- 交互入口要有明确 signifier，不能只依赖说明文字或偶然 hover。
- 3D 场景可以用 HTML overlay 做可读、可访问、易维护的轻量标注；本页已有投影函数，适合复用而非引入新渲染层。

我拒绝把铁匠铺改成任务雷达、游戏 HUD 或大面积教学遮罩。今天的转译是“铺内触点显影”：三位 NPC 和火炉旁出现四枚小炉扣，编号对应四站，点击后直接进入那一站。底部路线仍保留完整说明，炉扣只负责把可点性放回场景里。

## 创意方案竞争

### 方案 A：铺内触点显影

- 新颖度：4/5。前几轮完成了路线、物证、回执和当前站定位，但还没有把所有可点站点同时显影成场景里的操作入口。
- 访客价值：5/5。首次访客不用先理解底部 rail，也能从对象附近的编号炉扣知道“这里能点、点了进哪一站”。
- 场景贴合度：5/5。炉扣、站号和站名都属于铁匠铺导览语言，绑定的是既有 NPC 与火炉，不新增不相干内容。
- 视觉影响：4/5。首屏会同时看到四枚小触点，5 秒内能感知可交互目标；尺寸克制，不抢 NPC 和火炉主体。
- 实现风险：3/5。要处理多个 HTML overlay 的投影、遮挡底部导览、移动端尺寸和点击事件，但可复用上一轮站点投影逻辑。

### 方案 B：首次进入教学遮罩

- 新颖度：2/5。教学遮罩是常见模式，对这个已经有底部提示的页面不算新。
- 访客价值：3/5。能一次性说明“拖拽、点击、巡铺”，但会挡住首屏铁匠铺，且只在第一次有效。
- 场景贴合度：2/5。遮罩更像产品 onboarding，不像铺内自然标识。
- 视觉影响：4/5。非常明显，但明显来自覆盖层而不是场景。
- 实现风险：2/5。纯 DOM 状态即可，风险低，但容易变成额外说明文字。

### 方案 C：点击目标临近时对象发光

- 新颖度：4/5。在鼠标靠近或切站时让对应 NPC/火炉短暂发亮，会强化现场反馈。
- 访客价值：4/5。能帮助访客确认目标，但仍需要先知道可以 hover 或点击。
- 场景贴合度：4/5。炉光和热度反馈贴合铺子；如果过强会偏游戏化。
- 视觉影响：4/5。动效很明显，尤其在切站时能看到目标被点亮。
- 实现风险：4/5。需要遍历模型材质、处理 emissive 备份和还原，容易影响现有 GLB 材质或性能。

## 选择与完整体验

- 最终选择：方案 A，铺内触点显影。
- 访客会看到什么：首屏仍是铁匠铺、三位 NPC、火炉、当前站炉钉和底部四站路线；四个对象附近额外出现小号编号炉扣，分别标出 1 老杨、2 iLoop、3 近况、4 火炉。
- 访客能做什么：直接点击任一炉扣进入对应站点；炉扣会随相机移动保持贴近目标，当前站更亮，已看站点有完成状态。
- 访客得到什么：可点击对象不再藏在说明文字里，底部路线和 3D 场景形成双向入口；访客能更自然地从“看见对象”进入“理解老杨、iLoop、近况和火炉”。
