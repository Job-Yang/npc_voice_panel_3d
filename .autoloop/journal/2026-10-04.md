# 2026-10-04 自迭代手记

## 现状分析

今天开局工作区干净，`main` 与 `origin/main` 同步；`.autoloop/runs/2026-10-04_attempt_01` 里只有 supervisor 预检材料，没有今天未完成的 input 或 journal。主人反馈仍然是两条：页面必须独立于个人主页；需要新 3D 模型时不能手搓最终模型。

最近多轮都在四站巡铺、炉牌、聚焦光和声音状态上做加法与减法。昨天的“炉声火候”让右上角多了一条声音状态，桌面体验清楚了，但我今天复看移动端 CSS 时发现一个更基础的问题：在 320px 级别手机上，控制面板、稳火、舒缓/火炉、音乐都挤在标题下方同一条横向空间里，存在贴边和重叠风险。

所以今天不新增内容、不改 3D 模型、不碰相机和音频时序，只修移动端首屏控制布局。这个改动很小，但它直接影响访客第一下能不能点准，算是入口体验的硬质量。

## 输入如何变成想法

我吸收的是“移动端控制不能只靠缩小桌面布局”的原则。铁匠铺的按钮不多，问题不是需要隐藏，而是需要重新分层：标题先稳住身份，常用控制按左右放手边，炉声状态作为一条读数放在按钮下方。

转译成铁匠铺自己的表达，就是“掌中炉台分层”：像把炉前工具从一条拥挤边沿摆成两层可拿的炉台。桌面保持既有构图，手机上控制面板和音乐在第一层，稳火和场景模式在第二层，炉声状态再往下，底部巡铺不改。

## 创意方案竞争

方案 A：掌中炉台分层。新颖度 3/5，它不是新叙事，而是把手机首屏控制从拥挤按钮排成两层炉台；访客价值 5/5，手机访客能更容易点中控制面板、稳火、模式和音乐；场景贴合度 4/5，像把炉前工具按手边顺序摆开，不改变铁匠铺叙事；视觉影响 3/5，桌面几乎不变，手机首屏顶部更清楚；实现风险 2/5，主要改移动端 CSS 和调试取证，不碰高风险渲染与音频。

方案 B：完巡后的复访炉票。新颖度 4/5，四站走完后给访客一个“下次进铺先看哪里”的复访提示；访客价值 4/5，能强化离铺后的记忆点；场景贴合度 5/5，炉票语境贴合；视觉影响 2/5，默认首屏不明显；实现风险 3/5，会继续加重已经密集的炉牌文案。

方案 C：键盘巡铺补全。新颖度 3/5，补 Escape、Home、数字键等键盘巡铺；访客价值 4/5，对键盘用户有帮助；场景贴合度 3/5，工程质量强但现场感较弱；视觉影响 1/5，默认不可见；实现风险 3/5，全局键盘事件要避开彩蛋输入和对话按钮，容易引入意外触发。

最终选择方案 A。它不是默认选最小改动，而是选择了当前最挡路的入口质量问题：如果手机第一屏按钮互相挤压，后面的巡铺、声音状态和炉牌再完整也会先丢手感。方案 B 更有叙事味，但今天会继续堆文字；方案 C 值得做，但不是移动端首屏的第一优先级。

## 今天的想法

做“掌中炉台分层”：把移动端顶部控制从单行挤压改成两层稳定触控区，并把炉声状态下移为清楚读数。

访客会看到什么：桌面不变；手机上标题下方先是控制面板和音乐，下一层是稳火和舒缓/火炉，下面再是炉声状态。

访客能做什么：在窄屏上也能稳定点开面板、切稳火、切场景模式、开关音乐，再继续按底部四站巡铺。

访客得到什么：第一屏的操作更像可拿可点的掌中炉台，减少误触和遮挡，进入铁匠铺的第一步更稳。

## 为什么这么做

这几天已经连续补了很多导览层，页面能力不缺，缺的是移动端控制区的手感兜底。昨天新增炉声状态后，手机上顶部纵向空间更紧；如果不处理，声音状态虽然更清楚，按钮却可能互相压住。

我没有新增复访文案，因为炉牌和离铺炉票已经足够密，再写会让底部重起来。也没有补键盘快捷键，因为本轮公开输入更直接指向触控目标和响应式布局，手机入口问题更容易被普通访客感知。

预期改善是可验证的：320px 手机视口下，控制面板、稳火、模式、音乐、炉声状态和顶栏的矩形不相交；主要按钮高度提升到 40px，虽然没有完全做成 48px，但比原先更接近触控建议，也比 WCAG 2.2 AA 的 24px 门槛更稳。

## 做了哪些事

- 修改 `index.html`：
  - 在 `max-width: 640px` 样式里把顶部控制分成两层：第一层控制面板和音乐，第二层稳火和场景模式。
  - 将移动端控制按钮统一为 40px 高、固定左右留边，并把炉声状态、侧边面板和移动端对话框整体下移，避免互相覆盖。
