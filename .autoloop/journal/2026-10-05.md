# 2026-10-05 自迭代手记

## 现状分析

今天开局工作区干净，`main` 与 `origin/main` 同步；本轮 `RUN_DIR` 里只有 supervisor 预检材料，没有 2026-10-05 的 input 或 journal，需要从今天这一轮重新完整留档。主人反馈仍然是两条：铁匠铺必须独立于个人主页；需要新 3D 模型时不能手搓最终模型。

最近多轮重点都在四站巡铺、炉牌、炉声和手机控制区。昨天刚做完“掌中炉台分层”，解决的是窄屏入口控件拥挤。今天复看页面时，我看到另一个方向：四站内容已经很完整，但站点差异主要靠底部文字、按钮和标签表达，3D 空间本身仍然偏统一。访客切到老杨、iLoop、近况、火炉时，空间里的反馈更多是同一套暖色焦点环。

所以今天不新增模型、不继续堆炉牌文案，也不重排手机顶部，而是让既有空间反馈更能表达四站语义：身份、方法、试火、反馈各自有不同火候。

## 输入如何变成想法

我吸收的是“空间本身要参与叙事”的原则，而不是复制外部案例的多房间、大地图或游戏化任务。铁匠铺只有一间铺子，不能把它改成展馆迷宫；但它已经有四站路线，完全可以让每站的火候不同。

转译成铁匠铺自己的表达，就是“四站火候换色”：老杨站保留暖金身份火候，iLoop 站用蓝白方法火，近况站用青绿试火，火炉站用赤橙反馈火。它影响既有焦点环、空间热点、路线节点和一盏轻量 3D 补光，不新增最终模型，也不改变四站主线。

## 创意方案竞争

方案 A：四站火候换色。新颖度 4/5，不是新增物件，而是让同一间铁匠铺按站点改变火候语义；访客价值 4/5，访客切站时能通过焦点环、路线节点和局部光知道当前段落；场景贴合度 5/5，火候、炉色和落锤是铁匠铺自己的语言；视觉影响 4/5，iLoop、近况和火炉站会出现明显不同的蓝白、青绿、赤橙反馈；实现风险 3/5，需要改 CSS 变量、站点状态和灯光，但不碰模型加载、相机和贴地逻辑。

方案 B：键盘巡铺补全。新颖度 3/5，补数字键、Home、Escape 等键盘入口是常规质量提升；访客价值 4/5，对键盘用户有帮助；场景贴合度 3/5，可达性重要但铁匠铺现场感较弱；视觉影响 1/5，默认画面几乎没有变化；实现风险 3/5，全局键盘事件要避开彩蛋输入和按钮焦点，容易误触。

方案 C：底部炉牌减负。新颖度 3/5，继续整理信息层，但最近多轮已经反复做过类似收束；访客价值 4/5，减少文字密度能让首次访客更容易扫视；场景贴合度 4/5，炉牌和巡铺语境贴合；视觉影响 2/5，主要是减文案和重排；实现风险 2/5，主要改 DOM/CSS，但容易重复前几天的炉牌主题。

最终选择方案 A。它不是默认选最低风险方案，而是补当前页面更关键的空间表达：四站已经有很多文字解释，今天应该让场景自己回应每一站。方案 B 值得做，但更像可达性专项；方案 C 有用，但和最近多轮的收炉、轻读、炉牌收束太接近。

## 今天的想法

做“四站火候换色”：访客切换老杨、iLoop、近况、火炉时，空间焦点、路线节点和一盏 3D 局部补光同步切换成身份暖金、方法蓝白、试火青绿、反馈赤橙。

访客会看到什么：默认老杨站仍是暖金；进入 iLoop 会看到蓝白方法火，进入近况会看到青绿试火，进入火炉会看到赤橙反馈火。

访客能做什么：继续用原来的四站按钮、空间热点、人物和火炉巡铺，不需要学习新入口；切站时靠颜色和光感判断自己在哪一段。

访客得到什么：四站不再只是同一套按钮换文字，而是有了可感知的空间节奏，铁匠铺像按不同火候回应访客的每一锤。

## 为什么这么做

这几天已经把路线、炉牌、声音状态和移动端入口做得比较满。如果今天继续加底部解释，页面会更懂事但不一定更像 3D 互动页。外部输入都指向同一件事：沉浸式叙事需要空间、层次和段落感参与表达。

我没有新增模型，因为本轮不需要新物件就能完成主题，而且画像明确新最终模型要交给主人。也没有改相机和模型加载，因为四站定位、NPC 贴地和默认构图已经稳定，今天只应该改可回退的视觉反馈层。

预期改善是可验证的：`STATION_TONES` 中四站有不同 accent 和 light；`window.__SCENE_DEBUG__.stationFocus()` 会暴露当前 tone、label 和补光颜色；本地固定验证能证明页面仍能加载、canvas 存在、无 console error、无请求失败；截图能证明默认构图没有退化。
