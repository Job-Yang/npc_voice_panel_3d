# 2026-10-01 自迭代手记

## 现状分析

今天开局工作区干净，`main` 与 `origin/main` 同步；本轮 run 目录里只有 supervisor 和 preflight 证据，没有已经写了一半的 input 或 journal。主人反馈仍然是两条硬约束：铁匠铺要独立于个人主页；需要新 3D 模型时不能由我手搓最终模型。

最近一个月几乎都在四站巡铺的文本和路线层做加法：路签、炉牌、回声、完成回执、离铺炉票、昨天的匠印短句已经把“去哪、读什么、记什么”补得很厚。今天如果继续加文案，会让底部和右下 UI 更满，反而离 3D 铁匠铺本体更远。当前更明显的缺口是：访客切到某一站时，底部知道当前站，但眼睛还要自己去场景里找对应 NPC 或火炉。

所以今天不新增模型，不改默认相机，不动音乐和资源加载；主题改成空间注意力：让当前站在 3D 场景里有一枚可见但克制的“落锤聚焦光”。

## 外部输入与来源

本轮完整输入卡写在 `.autoloop/inputs/2026-10-01.md`。

我调查了 3 个公开来源：

- `Visitor Attention and Communication in Information-Based Exhibitions`：https://www.ijdesign.org/index.php/IJDesign/article/view/2144/742，访问日期 2026-10-01。看到信息型展览要通过呈现方式提升注意力和参与度，而不是只堆说明文字。

- `Museum Lighting`：https://ledworld.com.au/applications/museum-lighting/，访问日期 2026-10-01。看到博物馆灯光用重点照明建立视觉层级，引导观众注意重点展项和动线。

## 输入如何变成想法

我吸收的是“注意力要回到对象”和“用光建立层级”的原则。铁匠铺现在不缺路线解释，缺的是当前站与 3D 主体之间的可见关系。因此我没有做新展签，也没有新增场景模型，而是把外部输入转译成铁匠铺里的“落锤聚焦光”：当前站像被一锤点名，NPC 或火炉旁出现一枚暖色光环、细光束和短标签。

技术上没有引入 CSS2DRenderer，只复用现有 DOM 投影层和 `worldToViewport()`，让风险保持在 UI 标注层。小屏因为对话框和底栏已经很密，聚焦光改为跟随同站热点，避免遮住人物或读牌。

## 创意方案竞争

方案 A：落锤聚焦光。新颖度 4/5，它从文案导览转到空间注意力；访客价值 5/5，切站后立刻知道该看哪个对象；场景贴合度 5/5，像铁匠铺里的热痕和重点照明；视觉影响 4/5，默认和切站都有可见变化；实现风险 3/5，需要投影、移动端 fallback 和动效降级，但不碰模型和相机核心。

方案 B：2D 展签标签系统。新颖度 3/5，技术上贴近 three.js CSS2D 标签；访客价值 4/5，对象和说明更近；场景贴合度 4/5，展签适合展示页；视觉影响 3/5，默认会明显多标签；实现风险 3/5，容易和现有站点牌、读牌重复并遮挡画面。

方案 C：四站视角剧场。新颖度 4/5，每站自动给一个观看构图；访客价值 4/5，首次导览更强；场景贴合度 4/5，像师傅带看工位；视觉影响 5/5，变化最大；实现风险 4/5，涉及相机节奏、拖拽打断和移动端遮挡，可能削弱自由探索。

最终选择方案 A。它不是默认选最小改动，而是在最近多轮文本加厚后，把改善转向空间层；比方案 B 少堆 UI，比方案 C 少接管相机，更符合“独立 3D 互动页”的本质。

## 今天的想法

做“落锤聚焦光”：当前四站中的对象被轻轻圈出。桌面端聚焦光跟随当前 NPC 或火炉主体，显示“身份落锤 / 方法落锤 / 试火落锤 / 反馈落锤”；当前 NPC 头顶光源增强，火炉站炉膛补一点亮度。移动端则让光环绑定当前站热点，保留聚焦反馈但不压住对话和底栏。

访客会看到什么：默认老杨站多一枚暖色光环；切到 iLoop、近况或火炉时，光环和短标签随当前站移动。

访客能做什么：照常拖拽、点击 NPC、点火炉或用四站路线切换；每次切站都能用空间聚焦确认当前对象。

访客得到什么：底部路线和 3D 场景主体终于连起来，不用在说明和模型之间来回猜。

## 为什么这么做

昨天已经解决“点开后记住什么”，今天继续加一句文案只会重复。真正能提升首屏体验的是让 3D 场景参与导览：当底部写着 iLoop，画面里也应该有一个明确但不吵的焦点告诉访客“看这里”。

我没有选完整展签系统，因为页面已有站点牌、热点、读牌、炉牌和对话框，再加展签会让界面更满。也没有选视角剧场，因为自动视角虽然有冲击力，但会触碰中风险相机体验，并可能把页面推向强引导而不是可探索展示。落锤聚焦光的权衡更合适：它有明显视觉变化，但仍尊重访客自己拖拽和巡铺。
