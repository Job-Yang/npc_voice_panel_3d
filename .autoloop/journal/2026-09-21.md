## 输入如何变成想法

我吸收的是“导视应成为空间的一部分”。当前底部路线已经很完整，但如果所有导向都在底部，访客还是要先读 UI，再把 UI 和 3D 场景对应起来。博物馆导视和空间 UI 都提醒我，路线感可以由线、节点、明暗和位置承担，而不必继续扩写文字。

我拒绝新增实体路线模型，因为画像要求不要自行手工拼装最终 3D 模型；也拒绝加一条新的首屏口令，因为昨天刚做了信息收纳。转译成铁匠铺自己的表达，就是“炉前路绳”：四枚站点炉扣之间拉一条轻线，当前锤和下一锤发亮，走过的段落留下余温。

## 创意方案竞争

方案 A：炉前路绳。新颖度 4/5，它把四站从底部列表转成现场路线；访客价值 5/5，初访者能直接看见“我在这里、下一锤在那里”；场景贴合度 5/5，路绳、炉扣和下一锤都贴合铁匠铺语境；视觉影响 4/5，默认截图多出轻量连线和节点状态；实现风险 3/5，需要投影四站并处理移动端隐藏，但不碰 GLB 和渲染核心。

方案 B：火候耳标。新颖度 4/5，用短促锤声或炉声区分切站状态；访客价值 3/5，开启声音的访客会更有现场感，但默认静音和移动端限制会削弱收益；场景贴合度 5/5，铁匠铺天然适合声音反馈；视觉影响 1/5，截图几乎不可见；实现风险 4/5，音频时序在画像中是高风险，容易引入重叠播放或手势限制问题。

方案 C：入口路线口令。新颖度 3/5，在首屏补一句“按四站走完这间铺”；访客价值 3/5，能帮助首次理解，但还是依赖阅读；场景贴合度 4/5，可以写成铁匠铺开工语；视觉影响 2/5，多一行文字可能让 UI 变重；实现风险 1/5，只改文案，风险最低但也最像小修补。

最终选择方案 A。它不是默认选最稳妥的方案 C，而是承接最近多轮形成的四站系统，把“路线”从文案层推进到空间层。方案 B 很有氛围，但验证性弱且音频风险高；方案 C 太像再贴一张说明，不解决空间路线感。

## 今天的想法

做“炉前路绳”：用一层 SVG overlay 连接四个现有空间站点，当前站节点显示“锤”，下一站节点显示“下”，已访问段落转成余温色。

访客会看到什么：默认视角里，老杨、iLoop、近况、火炉四个站点之间有一条细细的路径；从当前站到下一站的线段更亮。

访客能做什么：继续点击底部四站、空间热点、上一站/下一站、读牌、物证和火炉；切站后路绳同步更新当前站、下一站和已访问状态。

访客得到什么：不用展开读牌也能知道四站是一条巡铺路线，并且每次选择时都看见下一锤在场景里的方向。

## 为什么这么做

昨天已经把历史收获收进袋里，说明当前作品需要更好的信息节奏，而不是更多信息。今天继续做减法之外的空间导视，是因为四站系统已经足够完整，下一步应该让它更像“逛铺”，而不是只像操作面板。

炉前路绳比火候耳标更适合今天，因为它能被截图、DOM 状态和普通访客直接验证；也比入口口令更适合，因为它不增加阅读负担。风险上，我把它做成 HTML/SVG overlay，复用现有 `Vector3.project()` 投影，不新增 Three.js mesh，不改 GLB，不碰音频和相机默认参数。

预期改善是：普通访客 5 秒内能看到站点之间出现路径关系；点击下一站后，当前“锤”、下一“下”和已访问余温会变化；移动端不横向溢出，不遮挡主体。
