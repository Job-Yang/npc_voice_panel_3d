# 2026-09-18 自迭代手记

## 现状分析

今天工作区开局干净，`main` 与 `origin/main` 同步。本日 attempt 目录只有 supervisor 预检文件，没有本日 input 或 journal，说明不是续写半成品创意。

最近十几轮都在打磨“四站巡铺”：从当前站、读牌、物证、站内行动、完成炉印、接力、炉屑袋，到昨天的下一锤路标，路线已经能把老杨、iLoop、近况和火炉串起来。今天看到的主要缺口不是内容不够，也不是需要继续摆新装置，而是页面的持续动效缺少一个“收住火候”的入口：火光闪烁、NPC idle、热点缩放、气泡过渡和相机飞行都在帮助氛围，但对想慢读内容或系统设置了减少动态效果的访客，这些动效应该可以降低。

所以今天做一轮非堆物件的体验改善：稳火阅读模式。目标是保留独立 3D 铁匠铺、四站导览和可点击反馈，同时让访客能一键降低非必要的持续动效。

## 外部输入与来源

本轮完整输入卡写在 `.autoloop/inputs/2026-09-18.md`。

我调查了 3 个公开来源：

- `prefers-reduced-motion`：https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion。看到系统减少动态偏好应该被页面检测，并用于移除、降低或替换非必要动效。
- `Understanding SC 2.2.2: Pause, Stop, Hide`：https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide。看到自动开始、持续超过 5 秒、与其他内容并行的运动需要暂停、停止或隐藏机制。
- `Technique C39: Using the CSS prefers-reduced-motion query to prevent motion`：https://www.w3.org/WAI/WCAG22/Techniques/css/C39.html。看到 `prefers-reduced-motion` 是可测试的降低动画方法，但本仓还需要同时处理 JS 驱动的 WebGL 动效。

## 输入如何变成想法

我吸收的是“减少非必要动态，不等于取消体验”。铁匠铺最重要的是空间、人物、火炉和巡铺内容，不是每一帧都在跳动。把它翻译成铺内语言，就是“稳火”：火还在，炉还亮，访客仍能逛，但火苗、人物和界面不再一直抢注意力。

我拒绝把页面做成静态模式或隐藏 3D canvas，因为那会偏离独立 3D 互动页。也拒绝只写 CSS media query，因为火焰和 NPC 的关键动效在 JS 渲染循环里，单靠 CSS 不能真正降低运动。

## 创意方案竞争

方案 A：稳火阅读模式。新颖度 4/5，它不是继续增加路线内容，而是把可访问性做成铁匠铺自己的火候控制；访客价值 5/5，对怕晃、想慢读、移动端停留更久的人直接有用；场景贴合度 5/5，“稳火”符合铁匠铺语境；视觉影响 3/5，默认新增一个按钮，开启后动效明显收敛但截图差异有限；实现风险 3/5，要碰渲染循环、相机补间和 NPC 动作速度，但不改模型加载和默认相机。

方案 B：火候节律条。新颖度 3/5，把火焰强弱和场景模式做成可见读数；访客价值 3/5，能解释状态但不能减少动效干扰；场景贴合度 4/5，火候读数贴合；视觉影响 4/5，截图变化更明显；实现风险 2/5，只改 DOM 和 CSS。它更像说明已有状态，不解决今天看到的舒适度缺口。

方案 C：静看一锤导览。新颖度 4/5，每次进站先短暂定格再恢复；访客价值 4/5，对读站点内容有帮助；场景贴合度 4/5，锤落后停一下的隐喻成立；视觉影响 3/5，切站时有感；实现风险 4/5，需要管理定时恢复、手动控制和站点切换之间的状态，复杂度偏高。

最终选择方案 A。它不是默认选最稳的小 UI，而是把持续动效这个底层体验问题纳入巡铺体验：让页面更能照顾不同访客，又不把铁匠铺变成静态说明页。

## 今天的想法

做“稳火阅读模式”：右上角新增稳火按钮，页面初始读取系统 `prefers-reduced-motion`；开启后，火焰闪烁、火苗形变、NPC 自动响应、NPC idle 速度、相机飞行动画和界面弹跳都明显收敛。

访客会看到什么：默认还是铁匠铺、三位 NPC、火炉和四站导览，右上角多一个“稳火”按钮；开启后按钮显示“稳火开”，画面保留但更安静。

访客能做什么：继续拖拽、缩放、点击四站、读牌、鉴定物证和点火炉；稳火只影响非必要动效，不拿走核心交互。

访客得到什么：在保留场景感的前提下，获得一个更适合慢读和低运动偏好的巡铺状态。

## 为什么这么做

过去几轮把导览链路越做越完整，但内容变多之后，页面要开始照顾“读”的体验。铁匠铺的火和人物动起来很有气氛，可它们不是每个访客都需要的。一个稳火入口能把主动权交还给访客：想看热闹就保持默认，想读清楚就稳住火候。

这个方案比火候节律条更实际，因为它直接减少干扰；比静看一锤更可控，因为它不偷偷替访客暂停和恢复，而是提供清晰开关。它也符合主人 2026-08-26 的反馈：不靠手搓新模型或新物件证明迭代，而是在现有页面里提高体验质量。
