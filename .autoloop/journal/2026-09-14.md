# 2026-09-14 自迭代手记

## 现状分析

今天工作区开局干净，`main` 与 `origin/main` 同步；本日 attempt 目录只有 supervisor 预检材料，没有本日 input 或 journal，可以从新一轮开始。

最近几轮一直在补“四站巡铺”的理解链路：路线、进度、物证、鉴定、空间炉钉、炉扣、站前读牌、行动锤和完成炉印都已经做完。现在它的问题不再是“内容不够”，而是默认底栏变得太密：首次打开时，当前站、问题、带走、行动、进度、物证、站点按钮一起出现，访客很容易先读底栏，而不是先看 3D 铁匠铺和人物位置。

所以今天不加新站点、不加新模型、不继续扩大完成回执，而是做一次信息层级整理：把深读信息收进“读牌”，让默认路线更轻，想深入时再展开。

## 外部输入与来源

本轮完整输入卡写在 `.autoloop/inputs/2026-09-14.md`。

我调查了 3 个公开来源：

- `Progressive Disclosure in UX Design`：https://supercharge.design/articles/progressive-disclosure-in-ux-design。看到渐进披露通过减少同屏复杂度来降低认知负担，先给最必要的信息，再让用户主动展开细节。
- `Exhibition Labelling`：https://mgnsw.org.au/sector/resources/online-resources/exhibition/exhibition-labelling/。看到展览标签要有层级：入口、主题区域、单件说明分开处理，视觉符号和一致样式帮助访客快速理解。
- `Creating Text`：https://threejs.org/manual/en/creating-text.html。看到 three.js 场景里的高质量说明文字可以用 DOM + CSS overlay 承接，不必把所有文字做进 3D 几何。

## 输入如何变成想法

我吸收的是“先给主线，再给细节”和“展览说明要分层”。转译到铁匠铺里，就是把底部巡铺栏拆成两层：常显层保留当前站、短句、行动按钮、进度和四站按钮；读牌层才显示问题、带走结论和物证。

我拒绝继续做空间标签或小地图，因为现有 station pin、炉扣和底部路线已经足够指路；也拒绝做自动欢迎弹层，因为自动打断会和 NPC 气泡、对话框抢注意力。今天的目标是减轻默认画面，而不是再加一个主动弹出的东西。

## 创意方案竞争

方案 A：巡铺读牌分层 · 首屏轻一点。新颖度 4/5，这是对连续几轮导览信息的层级重构，不是简单删文案；访客价值 5/5，首次进入时更容易先看 3D 铺子和当前行动，深入阅读仍然一键可达；场景贴合度 5/5，读牌像展览标签，贴合铁匠铺参观；视觉影响 4/5，默认底栏高度下降，展开后保留原信息深度；实现风险 2/5，只改 HTML/CSS 和少量状态逻辑，主要验证移动端溢出。

方案 B：首次进门自动短讲。新颖度 3/5，自动欢迎并不新，而且已有 NPC 气泡；访客价值 3/5，能提示入口，但可能打断看铺子；场景贴合度 4/5，老杨迎客合理；视觉影响 3/5，首屏更热闹但可能遮挡主体；实现风险 3/5，要处理加载时机、自动闲聊和音频解锁。

方案 C：四站路线迷你地图。新颖度 4/5，空间小地图能让站点关系更直观；访客价值 4/5，但和已有 3D 炉扣、station pin 重复；场景贴合度 4/5，像展馆导览但偏工具化；视觉影响 4/5，会新增明显 UI 元素；实现风险 4/5，桌面和移动端都要处理位置、点击和遮挡。

最终选择方案 A。它不是风险最低的纯文案修补，也不是最显眼的视觉加法，而是承接最近几轮累积后的必要整理：让导览内容继续存在，但不再默认把所有信息压到首屏。

## 今天的想法

做“巡铺读牌分层”：访客进入页面时，底部路线只显示当前站主线、行动和进度；点击“读牌”后，展开本站问题、带走结论和物证，再次点击可以收起。

访客会看到什么：3D 铁匠铺、三位 NPC、火炉和四个空间炉扣保持不变；底部路线默认更轻，右侧出现“读牌”按钮。

访客能做什么：按四站继续巡铺，或者展开读牌查看本站更深的说明、鉴定物证、切换物证。

访客得到什么：第一次看页面时更容易先理解“我在哪、下一步点什么”，需要细节时仍能读到完整展签。

## 为什么这么做

前几轮的每个增量单看都成立，但合在一起后，默认底栏已经从“路线”变成“信息面板”。继续增加内容会让它更重。今天选择分层，是因为它能保留已有劳动成果，又把默认注意力还给 3D 场景。

这个改动也符合画像里的安全区：只改声明式导览层和 HTML 状态，不碰 GLB、相机、灯光、BGM 和渲染循环。风险主要是移动端展开读牌后遮挡或横向溢出，所以验证里专门检查桌面和移动端收起/展开高度与 `overflowX`。
