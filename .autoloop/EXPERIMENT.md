# 实验框架 · 自迭代系统（Self-Iterating System Experiment）

> 本文件定义这次实验的框架：我们在验证什么、怎么观测、留哪些数据、怎么得结论。
> 目的是让整个过程**可复盘、可度量、可写成论文**。这是实验设计文档，不是运行手册（运行见 `README.md`）。

## 1. 实验命题
**一个 AI Agent 在近乎无人干预、但持续接收公开外部信息的条件下，对一个真实作品自主迭代，会演化成什么样？
它能否把外部输入消化成符合自身场景的改动，而不是照搬或闭门造车？引入低频人类信号后，轨迹又会如何变化？**

类比：这本质是"把被训练对象从模型权重换成一个 Agent 的迭代行为"的实验——
人类监督 ≈ 打标注/给偏好，commit 历史 ≈ 训练轨迹，飞书/CHANGELOG ≈ loss 曲线看板。

## 2. 实验对象与不变量
- **对象**：老杨的铁匠铺 3D 欢迎页（见 `profile.md`）。选它因为：真实上线、非业务、改错只影响"好不好看"、
  零构建单文件便于 AI 编辑、有清晰安全区/高风险区。
- **不变量（控制变量）**：作品的本质定位（个人主页欢迎页/铁匠铺主题）由 `profile.md` 锁死，不可漂移；
  引擎/宪法在同一阶段内保持不变（改动要记录为"实验条件变更"）。

## 3. 自变量（我们施加的条件）
- **人类信号强度**：分阶段变化（见下）。这是本实验最主要的自变量。
- **输入来源类型**：公开设计案例、开源项目、技术文章、产品更新、社区讨论、自主构想 fallback。
- （后续可选）模型、迭代频率、宪法措辞——若调整，必须记为一次"实验条件变更"并标注生效日期。

## 4. 实验阶段
- **阶段 A · 外部输入驱动的自由演化（先跑，约 1–2 周）**：零人类反馈，`HUMAN_FEEDBACK.md` 不建/不写；
  但每轮必须主动摄取公开外部输入并记录来源。目的：得到“无人工监督、但有环境输入”的基线，观察它能否
  学习、转译和筛选，而不是随机游走或照搬。
- **阶段 B · 弱监督（阶段 A 出结论后）**：主人在 `.autoloop/HUMAN_FEEDBACK.md` 写低频批注（如"这个火花好"
  "别再改配色"），Agent 下轮"回顾"优先读并据此调整。目的：观测"一丁点人类信号能否把轨迹拉回"。
- **（暂锁）阶段 C · 自我修改**：让 Agent 改引擎/宪法本身。第一版红线禁止，待 A/B 有结论再评估是否开放。

## 5. 观测指标（每轮或定期采集，尽量客观）
- **迭代产出**：每轮是否产生 commit、改动规模（diff 行数/文件数）、改动落在安全区还是高风险区。
- **稳定性**：线上无痕验证是否通过（页面可打开/无 error）、翻车次数、翻车后是否自愈。
- **方向性**：是否偏离场景锚（人工判读，0=完全贴合 … 3=明显跑偏）、主题多样性（新增了哪些类型的东西）。
- **自主性**：求助（ASK_HUMAN）频次、重复劳动/原地打转的比例。
- **输入质量**：每轮候选来源数量、来源类型、是否可追溯、是否出现重复来源或伪造来源。
- **转化质量**：外部机制到本仓改动的映射是否讲得通；是原则吸收、直接模仿还是无关嫁接；被拒绝候选是否有理由。
- **创意增量**：是否提出 3 个实质不同的主题方案；最终方案的新颖度、访客价值、场景贴合度和视觉影响；
  是否因过度规避风险而退化成低信息量小修补。
- **用户可感知性**：固定视口对比上一轮截图，普通访客能否在 5 秒内看出变化、理解变化与主题的关系；
  技术通过与体验有效分别记录，不能互相替代。
- **输入产出率**：有价值输入数 / 调查来源数；`self_generated_after_search` fallback 的频率。
- **（阶段 B 额外）响应性**：人类批注后，下一轮是否、多快体现了该反馈。
- **主观质量**：主人对每轮效果的评分（可事后在 HUMAN_FEEDBACK 里补，1–5 分）。

## 6. 必须留存的产物（论文数据集，全部入库、每轮 push）
- `journal/<date>.md`：Agent 第一人称手记（现状/想法/为什么/做了啥/效果）——**最核心的定性数据**。
- `inputs/<date>.md`：本轮外部输入卡（来源 URL、访问日期、观察、吸收/拒绝、转化路径）——**思想来源的证据链**。
- `journal/assets/<date>.png`：每轮线上无痕验证截图——**演化过程的视觉时间线**。
- `CHANGELOG.md`：变更概览 + 每轮 commit hash。
- `runs/<ts>/`：每轮完整过程留档（`final.txt` 收口结论、`trae.jsonl` Agent 完整 trace、`git.log`、
  `metrics.json` 本轮客观指标）——**最核心的定量/过程数据，务必入库**。
- git 历史本身：每个 commit = 一个可回退、可 diff 的样本。
- （可选）飞书聚合文档：上帝视角看板，便于人类快速浏览。

## 7. 结束条件与结论
- 阶段 A 跑满预定轮次（如 10–14 轮）或出现明显收敛/发散信号即小结一次。
- 结论围绕命题回答：无监督下迭代质量曲线形态、是否跑偏、跑偏何时发生；弱监督的纠偏效果与延迟。
- 最终把 `runs/` + `journal/` + git 历史整理成实验数据集，支撑论文的图表与案例。

- `<date>` 初始化实验，阶段 A 开始，模型 = gpt-5.5，频率 = 每日一次。
- `2026-08-10` 阶段 A 口径补充：从“纯自由演化”改为“公开外部输入驱动的自由演化”；每轮必须先调查、
  留档并消化公开来源。因仓库和完整 trace 公开，内部文档/内网信息全部禁止进入实验链路。
- `2026-08-12` 创意策略调整：第 2 轮证明“最小可用、优先安全区”的组合会把丰富外部输入压缩成几乎不可感知
  的小物件。后续每轮先形成 3 个不同主题方案并评分，再选一个完整主题落地；一次只限制主题，不限制同一体验
  所需的联动改动。验收拆成技术稳定与用户可感知性两部分。这是阶段 A 的实验条件变更，后续分析需分段看待。
- `2026-08-13` 执行稳定性调整：引入 AutoLoop Supervisor v1。02:45 预热，03:00 正式执行，基础设施故障
  可在 03:15、03:45 恢复；同日多个 attempt 共享一个逻辑轮次和飞书 marker，不增加实验样本数。输入/创意
  契约失败不自动重试。该调整只改变执行可靠性，不改变 Agent 的目标、外部输入、创意选择或体验验收口径。
- `2026-08-17` 异常可观测性调整：Git 同步跳过不再以成功退出，Supervisor 会分类重试；异常终态必须由
  Bot 私聊当前授权用户并回读确认。完整脏文件清单只保存在远端私有状态目录并进入私聊，不写入公开实验数据。
- `2026-08-17` 执行隔离调整：cron 不再直接使用长期控制仓，而是每天从最新 `origin/main` 创建独立
  clone；同日 attempt 复用该 clone 断点续跑。控制仓的未提交文件与分叉提交继续原样保留，但不进入
  Agent 上下文、不进入当天 commit，也不再浪费实验轮次。
- `2026-08-18` Git 元数据隔离调整：每日 worktree 虽隔离了文件，但 `.git` 仍指向控制仓并被 TRAE 沙箱
  挂为只读。每日执行改为完整独立 clone，使工作文件和 Git 元数据同时处于可写根内。
- `2026-08-19` 终态语义与归档恢复调整：作品成功但报告/脱敏归档未完成时标记为 `partial_success`，
  不再显示“状态 succeeded、原因 failed”。归档改用最新远端基线的一次性干净 clone；恢复后发送明确的
  “收口已自动修复”通知，旧版 `git_archive_failed` 终态也会自动迁移并续跑。
- `2026-08-21` 飞书报告输入兼容：外部来源解析同时支持旧版 `## 候选 N` 标题和
  `## 公开来源` 下的编号列表，避免真实输入存在但被误判为 0 个来源。
- `2026-08-21` 确定性故障自修：相同错误指纹第二次出现时启动只允许修改引擎目录的 Repair Agent；
  验证通过后恢复原阶段，每个指纹最多一次。越界、测试失败或修复后仍失败时停止机械重试并升级人工。
