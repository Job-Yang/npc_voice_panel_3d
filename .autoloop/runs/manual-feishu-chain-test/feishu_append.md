# 2026-08-10 自迭代手记

## 现状分析

这是第一轮正式唤醒。CHANGELOG 还停在“未开始”，journal 里只有说明文件，没有历史手记；也没有看到主人额外写的 HUMAN_FEEDBACK。页面本体已经很完整：有铁匠铺 3D 场景、三个 NPC、火炉/铁砧/水桶/工作台这些可点物件，也有 iLoop 彩蛋、BGM 和场景模式。

我今天看到的主要缺口不是“还不够热闹”，而是 iLoop 这个主人核心身份还偏多依赖右下角对话文案。访客能点到 YQ 或工作台，但“计划、取证、验证、收口”这条方法论还没有一个场景里的实物锚点。作为个人主页欢迎页，它应该让访客不用读很长介绍，也能从场景物件里摸到老杨的工作方式。

## 今天的想法

灵感来自一次简短联网检索：同类 3D portfolio 常用可点击 marker、工作台、终端、展品等物件承载项目叙事，而不是只靠文字卡片。我决定加一个“闭环卷轴 / 计划板”小物件，放在工作台旁边，点击后讲清 iLoop 的证据链。

## 为什么这么做

我没有选择新增 NPC、改灯光或大改相机，因为这是第一轮，应该先在安全区做一个小而可验证的增强。新增可点击物件符合画像里的鼓励方向，也不会改变作品本质：它仍然是老杨的铁匠铺个人主页欢迎页，只是把“认识老杨 + 感受手艺人气质 + 找到 iLoop 入口”做得更直观。

这个改动的预期收益是：访客在探索工作台附近时，会看到一个额外的场景线索，点击后知道 iLoop 不是抽象口号，而是一套计划、日志、截图、构建结果和真实验证串起来的工作方式。它也给隐藏的 iLoop 闭环彩蛋补了一个显性入口。

## 做了哪些事

- 修改 `index.html`：
  - 在 `OBJECT_CONFIG` 新增 `loopboard`，名称为“闭环卷轴 · iLoop 证据链”。
  - 在场景初始化时创建并注册 `loopboard` 交互物件。
  - 在 `makeProp` 里新增 `loopboard` 的几何体：木架、卷轴板、三个发光节点和连接线，表示计划、取证、验证的闭环证据链。
- 本地验证：
  - 启动 `python3 -m http.server 8123`。
  - 使用 Playwright + Chromium 打开 `http://127.0.0.1:8123/?t=local-loopboard-click`。
  - 因远端环境缺少浏览器依赖，先把 Playwright 浏览器缓存放到 `/tmp`，再把缺失的 `libgbm1` 和 `libwayland-server0` 以用户态方式解包到 `/tmp`，没有改系统目录。
  - 验证结果：页面加载完成，新增卷轴可点击，对话框显示“闭环卷轴 · iLoop 证据链”，控制台没有 error。只有自动播放和软件 WebGL 相关 warning，和本次功能无关。
