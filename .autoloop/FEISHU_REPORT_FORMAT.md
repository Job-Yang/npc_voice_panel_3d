# 飞书每日实验记录规范

版本：`AutoLoopReportSchema:v1`

本规范约束 AutoLoop 主实验文档中的每日记录。飞书是实验总览，不复制 GitHub 原始文件。

## 固定位置

- 所有成功轮次和失败运行都必须位于 `6. 实验记录`。
- `7. 阶段结论` 必须始终是最后一个一级章节。
- 每轮效果图放在该轮 marker 后、下一轮或阶段结论前。

## 成功轮次结构

每轮只能生成以下结构：

1. H2：`第 N 轮｜YYYY-MM-DD｜一句话主题`
2. 两列表格，行名和顺序固定：
   - `外部输入`
   - `现状与判断`
   - `本轮方案`
   - `改动`
   - `验证与效果`
   - `原始证据`
3. 机器标记：
   - `AutoLoopReportSchema:v1`
   - `AutoLoopRun:<timestamp>`
4. 本轮效果图

禁止：

- 把 input/journal 原文全文粘贴进飞书。
- 在轮次内部再次生成日期 H1，或把原始 Markdown 的 H1/H2 带入飞书。
- 使用作品最新 commit 代替本轮作品 commit。
- 把轮次追加到 `7. 阶段结论` 后面。

## 内容口径

| 行 | 内容 |
|---|---|
| 外部输入 | 来源链接 + 采用/拒绝/转译摘要 |
| 现状与判断 | 本轮看到的核心缺口，不写工具流水账 |
| 本轮方案 | 做什么、为什么做，保持场景约束 |
| 改动 | 主要文件和行为变化 + 本轮作品 commit |
| 验证与效果 | 本地/线上视觉结论、错误与边界 |
| 原始证据 | GitHub input、journal、run 链接 |

各行由确定性脚本裁剪长度。详细内容回到 GitHub 查看。

## 失败运行结构

失败运行不计入正式轮次，使用 H2：

`运行异常｜YYYY-MM-DD｜未形成有效实验轮次`

只记录状态、失败摘要和 run 链接，并放在 `6. 实验记录` 内。

## 机器门禁

同步成功必须同时满足：

- schema marker 为 `AutoLoopReportSchema:v1`。
- run marker 存在且唯一。
- marker 位于 `7. 阶段结论` 之前。
- marker 前存在本轮 H2。
- H2 和 marker 之间恰好有一张记录表。
- 表格包含六个固定行名，顺序一致。

任何一项不满足，飞书同步判失败，不允许只凭写接口返回成功收口。
